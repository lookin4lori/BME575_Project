### 2b. Classifier head — Kaiyao Hou

I built `scripts/classifier.py` on the team's DenseNet121 feature-extraction backbone. The head now follows the sequence described in the reference paper's §4.3: **global average pooling → fully connected classifier → softmax**. Since the project's task has two classes, its fully connected layer has two softmax outputs in the fixed order `[P(no DR), P(any DR)]`. The second probability corresponds to APTOS diagnosis grades 1–4; grade 0 is no DR. The paper specifies softmax and binary classification, but does not explicitly state the number of output units. Using two units is our implementation of its two-class setting. (Mohanty et al., *Sensors* 2023, 23, 5726, §§4.3–4.4; *HandoverNotes.pdf*, p. 5.)

The model compiles with Adam and sparse categorical cross-entropy. Sparse loss lets the existing `scripts/dataset.py` pipeline keep scalar class labels `0` and `1`, without one-hot encoding. For binary metrics and thresholding, use the **second** softmax column as the probability of any DR. The paper identifies Adam as its optimizer, but does not specify the binary loss implementation. Sparse categorical cross-entropy is our choice for the two-output softmax and existing labels. The input pipeline already applies DenseNet preprocessing to 224 × 224 RGB images, so the classifier does not preprocess them again.

`build_classifier` starts with the pretrained backbone frozen, leaving the classifier head trainable. `set_classifier_backbone_trainable` freezes it again or unfreezes a specified number of final dense blocks; batch-normalization layers stay frozen under the repository's default setting. A trainability change recompiles the model with a fresh optimizer so the updated trainable weights are included. This supports a frozen-feature baseline and optional later fine-tuning; the paper does not provide an exact unfreezing schedule. (*ML_ProgressReport1.pdf*, pp. 6, 8.)

The reference paper's DenseNet settings are batch size **32**, **50** epochs, initial learning rate **0.01**, and minimum learning rate **0.00005** (Table 4). These values remain in `config.py`. Dropout is **disabled by default** because the paper does not specify it; a configurable dropout layer remains available for team experiments. Neither the precise dropout rate nor the two-output loss should be presented as a published paper setting. (Mohanty et al., *Sensors* 2023, 23, 5726, §§4.3–4.4 and Table 4.)

This update aligns the classifier architecture with the paper's stated sequence; it does **not** claim to reproduce the paper's training run or reported performance. Any verification output generated for the previous single-sigmoid classifier belongs to that earlier implementation and must be regenerated for the two-output model. This section provides architecture and compilation functions, but does not define a complete training or fine-tuning schedule.

On 2026-10-16, the updated classifier passed the full repository test suite (46 tests and 2 subtests) and the real-image pipeline checks. A separate 20-image **training-subset diagnostic** using ImageNet weights, a frozen backbone, no dropout, and 50 repeated updates reduced loss from 0.6923 to 0.0032 and reached 20/20 correct on those same images. This confirms the head can learn and is **not** held-out accuracy or reproduction of the paper's reported performance.
